Terraform × GitHub Actions

You are looking at a page served by Azure Static Web Apps. The infrastructure that hosts it was created by Terraform, and every commit flows through a pipeline that authenticates with OIDC — no client secrets, no stored keys.

View the source How it ships

The pipeline

  1. 01

    Validate

    terraform fmt -check and terraform validate run on every push and pull request.

  2. 02

    Plan

    The plan is posted as a pull request comment, so reviewers see the exact diff before it is applied.

  3. 03

    Apply

    On main, the saved plan is applied — never a fresh one — behind a protected environment.

  4. 04

    Deploy

    The site is uploaded with the Static Web Apps deployment token, fetched at runtime with the Azure CLI.

Keyless by default

GitHub mints a short-lived OIDC token, Entra ID validates the issuer and subject, and the workflow gets a scoped access token. Nothing long-lived is ever stored in the repository.

Least privilege

The service principal is Contributor on one resource group and Storage Account Contributor on the state account — not on the subscription.

Remote state

State lives in a versioned, encrypted Azure Storage account. Locking is native blob leasing, so concurrent applies fail fast instead of corrupting.

Zero cost

Static Web Apps on the Free plan includes SSL, a global CDN and custom domains. The whole project runs at $0/month.
